# Set up Isolinear Memory

Copy this into an agent with local file access. Ordinary note work does not require
this setup prompt again.

```text
Set up or update Isolinear Memory for my selected folder. Discover its existing
instructions, provider, project identity and private state; preserve them. Read
https://github.com/Kian-hdr/isolinear-memory/blob/main/docs/INSTALL.md
and use its verified release installation procedure. Do not execute unverified
packages or replace history, credentials or existing instructions.

Choose the vault profile from my purpose: team/company knowledge keeps Raw/Wiki/Output;
personal memory uses concise natural notes without manual contributor logs or
mandatory verification templates; project memory uses folders designed for the
project domain, lifecycle, assets and deliverables. Projects can be shared teams:
retain person/agent contribution history and coordinated writing. Use setup
--vault-type team|personal|project and repeatable --project-folder for domain folders.
For a new project, establish its AGENTS.md, INDEX.md and brief/current handoff.
Use native file tools for ordinary notes; never reorganize a populated folder
automatically. Preserve identity, existing instructions and recoverable history.
Install a stable `isolinear-memory` command, preserve the compatible
`shared-memory` alias, and configure automatic local capture when supported,
so routine edits require no model-generated script or manual sync. Verify capture
with a bounded edit/history check. Preserve prior runtime versions for rollback.

Keep the routine instructions short: read INDEX and relevant notes only, update
existing canonical notes, preserve useful sources and material uncertainty, and place
generated deliverables in the selected layout's deliverable folder. Keep setup/troubleshooting details out of routine context.

Retain conflict copies, explicit read-only limits and selected-folder boundaries.
Use one provider; local history is not proof of remote receipt. Formats 1/2 need
backed-up migration, not a new identity. Respect host authentication/OS controls.
If capture fails, preserve saved Markdown, report the exact error once and continue
feasible note work. Report the installed version, actual capture status and limits.
The product name changed; do not rename `.shared-memory.json`, `.shared-memory/`,
project IDs, existing folders, or historical records.
```
